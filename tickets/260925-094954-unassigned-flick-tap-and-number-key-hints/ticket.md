## 未割当フリックをタップにし、方向ラベルと個別感度設定を揃える

### Why
<!-- ユーザ価値・解きたい問題を 1〜3 行で書く。
     Product Brief の Problem / Solution のどの部分を担うか明記する。 -->
Product Briefの「同じジェスチャー体系で素早く操作したい」を満たすため、割当のない方向へ指がずれても入力を失わず、テンキーの記号キーでは利用できるフリックをキー上で把握できるようにする。

このticketが終わると、Android利用者が未割当方向でも通常タップを入力でき、テンキーの記号フリックを見分け、テンキー方式とQWERTYの感度を別々に調整できる。

- [x] AC 1: フリック未割当方向へ動かしたキーは表示がフリック選択へ変わらず、移動に伴う追加振動もなく、離すと中央タップと同じ動作を一度だけ行う。割当済み方向、中心復帰、取消、長押しの動作は維持される。
- [x] AC 2: テンキーの`-`キー内には左`+`・上`/`・右`*`・下`,`、`.`キー内には左`,`・右`=`が方向に対応する位置へ補助表示される。`.`の未割当上下には補助表示がない。選択した方向の表示変化はEnterキーと同じ操作体系で見える。
- [x] AC 3: 製品ページの操作モックでも未割当方向のタップ確定とテンキー記号の方向ラベル・選択状態を同じように試せる。
- [x] AC 4: 設定画面に「かな・テンキー」と「QWERTY・記号」の独立したフリック感度設定があり、それぞれ「高い」「標準」「低い」を選べる。初期値は両方「標準」で、選択はアプリを終了・再起動しても保持される。
- [x] AC 5: 「高い」では「標準」より短い移動、「低い」では長い移動で割当済み方向が選択される。かな・数字レイヤーの設定を変えてもQWERTY・記号レイヤーの選択距離は変わらず、逆も同じである。変更は次に開くキーボードに反映される。
- [x] AC 6: どの感度でも未割当方向は通常タップとして一度だけ入力され、中心復帰・取消・中央長押し・Spaceのカーソル移動は維持される。
- [x] AC 7: 製品ページの操作モックでも二つの感度を別々に切り替え、同じキーと移動距離で選択の違いを試せる。表示する感度名と初期値はAndroid設定と一致する。
- [ ] AC 8: 「かな・テンキー」「QWERTY・記号」の各感度で、v0.15.24より短い指の移動でも割当済みフリックを選べる。未割当方向・Spaceのカーソル移動・音声・絵文字の操作は変わらず、製品ページのモックも同じ距離で選択される。

### Design Decisions
<!-- 既知の設計判断と理由を箇条書きで明示。
     例: - データ保存形式: data URI (Files API は将来 ticket、本 ticket では不要)
     例: - 423 reject ではなく 422: validation error として扱う -->
- 未割当方向は中央タップ相当とし、方向通過では追加振動・選択アニメーションを出さない。指を置いた瞬間の通常タップ振動は維持する。
- `-`は既存の左`+`・上`/`・右`*`・下`,`、`.`は既存の左`,`・右`=`を表示する。割当自体は変更しない。
- native表示、保存済みHTML/CSS正本、ブラウザモック、マニュアルを同じ判断へ揃える。
- かな・数字とQWERTY・記号の二組に、独立した「高い」「標準」「低い」の3段階設定を置く。初版v0.15.24では標準を旧値18dpに保ったが、2026-09-26のユーザ指示「それぞれもう少しゆるく」で各段階を短距離化する。
- 高い/標準/低いの選択開始は10/16/24dp（旧12/18/26dp）、中心復帰は6/9/13dp（旧7/10/14dp）、縦方向専用キーの軸固定は7/11/15dp（旧8/12/16dp）とする。いずれも一段階ずつ小さくする可逆な微調整。Spaceのカーソル移動距離・長押し時間・tapの当たり判定は変えない。
- 設定値は次に表示するキーボードから反映する。音声・絵文字の専用面には個別感度を適用しない。
